# 0.2.0 重构方案与验收

目标：将本机耦合的网页委托脚本整理为可独立审阅、安装、测试和提交 GitHub 的 MIT 项目，保留六类业务能力，并把个人配置与运行记录移出源码。

| 阶段 | 调整 | 验收证据 |
| --- | --- | --- |
| 边界拆分 | 连接、网页机械操作、任务流程、命令行和存储分层 | 可直接导入的模块；正式入口只转发到同一 CLI |
| 可移植性 | 显式 CDP 或适配器；不依赖相邻 skill | 未配置浏览器时 help/参数检查正常；适配器协议测试 |
| 生命周期 | 任务自有页、明确发送状态、一次发送、部分输出与清理 | 任务服务单测、真实 CLI 子进程、本地 Chrome |
| 数据正确性 | 内核所有权互斥、跨进程 quota 事务、损坏状态失败关闭 | 多进程并发计数、进程死亡恢复、损坏文件和 I/O 测试 |
| 图与账号 | 图下载校验、参考图保留、只按明确拒信限额；邮箱精确确认 | 图文件与 DOM 测试、账号状态机；邮箱/Google 切换、恢复与完整单图生成保存真实通过 |
| 公开交付 | MIT、README、SKILL、迁移、贡献/问题规范、CI、包白名单 | 源码/包检查、归档文件清单与敏感内容扫描 |

实施结果与实测范围见 [testing.md](testing.md)。本方案不把更换框架、增加付费 API 后端、自动轮换账号、自动发布 GitHub 或扩大外发权限作为重构内容。

## 保留的边界

- HTML 与选择器仍会随真实 UI 改版而失效；离线测试保证已知 DOM 契约，无法保证未来站点兼容。
- 账号切换只复用已存在的 SSO；邮箱无法核验时明确失败，密码/验证码由用户手动完成。
- 图片容器验证不等于完整像素解码；服务端额度仍只能从当轮返回与本地事件作有限判断。
- 跨平台 CI 已配置，只有实际运行结果可作为平台通过证据。

## 后续演进

先维护 DOM 夹具与真实站点冒烟记录，再考虑新的后端、站点语言或模型 UI。任何新增发送路径复用同一任务生命周期、互斥和消息归属协议，避免再次复制选择器和清理逻辑。
