# 证据标准：什么算"可独立核验"

> 实证来源：shouxie-mcp 第六、七、八轮——证据核验进行了三轮才闭环，缺口全部是**形式**而非内容。按本标准组织证据，一轮即可通过。

## 三值证据等级（发现/整改/判定的共同语言）

| 等级 | 含义 | 示例 |
|---|---|---|
| **源码确认** | 审查者直接读代码得出，不依赖任何声明 | "jobs.mjs:363 的队列在写入前重新检查注册表" |
| **测试验证** | 可执行的测试真实命中目标分支并断言结果 | "tests/jobs.test.mjs N2 用例注入第二次失败，断言 spawn=0" |
| **部署待验证** | 依赖外部环境，交付物内无法验证——**必须显式列出**，不得含糊 | "Windows 文件锁下的 rename 行为需部署期观察" |

## 复现记录的"可独立核验"清单（逐项满足，缺一不可）

1. **完整 40 位 commit SHA**（短哈希不满足独立核验标准——实证：第八轮前 manifest 用 16 位短哈希被拒）。
2. **仓库 URL** + 平台信息（OS/Node/npm 完整版本）。
3. `npm ci` 的**退出码**（记录为 0，不写"安装成功"）。
4. 两次 `npm test` 的**原始控制台输出**（tee 落盘，含测试总数/通过/失败行）。
5. 测试与 commit 的**关联可验证**：Git bundle（可 clone 后 `git checkout main && git rev-parse HEAD` 核对）或逐文件 SHA-256 清单（完整 64 位）。
6. **已知陷阱**（前轮实证）：bundle 不携带默认 HEAD 引用（clone 后需 `git checkout main`）；manifest 短哈希被拒；省略号直链被拒；URL 校验的 userinfo/空 query/hash 绕过变体。

## CI 记录的"可独立核验"清单

1. run 直链 + **headSha 完整 SHA**（与目标 commit 的关联是证据核心）。
2. 每个 job 的**独立结果**（conclusion）与直链——统计口径说明白（如"每 push 两次 run × 4 job"）。
3. CI workflow 定义文件随交付物提供（证明"应该执行什么"）。
4. 区分：workflow 定义 ≠ 该 run 实际执行成功——两者分开陈述（实证：第六轮复核明确做了这个区分）。
5. 复审环境若无法访问 GitHub，接受日志下载件（每个 job 一个 .txt，含 job ID/环境/版本/npm ci/npm test 完整输出）。

## 证据格式陷阱速查（实证清单，组织证据前对照）

- [ ] SHA 是完整 40 位（16 位短哈希被拒——第八轮）
- [ ] 直链是完整 URL（`.../job/xxx` 省略形式被拒——第八轮）
- [ ] bundle clone 后需 `git checkout main`（不携带默认 HEAD 引用）
- [ ] 端点/URL 样本过 userinfo / 空 query/hash / 路径穿越变体检查（第七轮复现）
- [ ] "workflow 定义在包里" 与 "run 实际成功" 分开陈述
- [ ] 声明与记录分离：**测试结果写在证据文件里 ≠ 独立核验通过**（第七轮原话）
